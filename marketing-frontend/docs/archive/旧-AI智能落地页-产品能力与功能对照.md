# AI 智能落地页智能体：产品能力 × 产品功能 / Agent 对照

> 依据《数字门户产品战略规划》（2026-09）承接层定位，以及闭环：  
> **意图 → 匹配页 → 到达路径 → 留资 → 用数据改匹配**  
> 设计原则：只保留闭环上不可缺的功能；能用现有玩法模板解决的，不另起一套模板。

---

## 1. 怎么读这张表


| 列        | 含义                              |
| -------- | ------------------------------- |
| 产品能力     | 闭环里必须成立的作业，不是菜单名                |
| 产品功能     | 后台/站点侧：对象、发布、配置、统计              |
| Agent 能力 | 模型 + 工具完成的判断/生成；没有 Agent 就只能人肉做 |
| 现状       | 相对当前营销落地页 Agent demo            |


能力 1～6 是本智能体闭环；K / C / S 是首期要对接、但不归本智能体独自实现的能力。

## 2. 总表：能力 → 功能 / Agent


| #   | 产品能力       | 要解决的问题       | 产品功能（系统）                                     | Agent 能力                             | 现状               |
| --- | ---------- | ------------ | -------------------------------------------- | ------------------------------------ | ---------------- |
| 1   | 意图库存       | 知道该接哪些流量     | 自动拉词进候选；人确认（或手建）成意图；对象可编辑/停用             | 把词判为了解/对比/决策                         | 无意图对象            |
| 2   | 按主题出页      | 出对得上的页       | 页面类型 + 阶段字段；对话创建；意图创建                         | 选默认页面类型；按类型写页；阶段改 CTA/表单；知识召回；确认门；质检 | 仅对话出页，无阶段        |
| 3   | 发布成站内真页    | 页必须有可引用的 URL | CMS 发布、路径、基础 Meta、绑定已有表单                     | 随文案写出 title/description              | 仅预览 HTML         |
| 4   | 分发到达       | 人能到达匹配页      | URL 目录与带参复制；进站后判断是否命中意图页；未命中可横幅引导（SSR） | 无（命中/横幅先走规则）                        | 无                |
| 5   | 转化承接       | 来了能留下线索      | 页上表单提交写入询盘，带 page / 意图 / UTM；客服开关            | 按阶段约束 CTA 和表单字段（在出页时完成，不另做转化 Agent）  | 页上有表单雏形，无 CRM 回写 |
| 6   | 效果回流       | 知道接没接住       | 按页、按来源：PV、表单提交                               | 无（不达标时人用对话改页）                        | 无                |
| K   | 知识基座对接     | 内容专业、不编造     | 企业库检索                                        | 写作前 RAG；无命中则藏模块                      | Mock             |
| C   | 与内容运营协同    | 把流量引到落地页     | 发文时可插入已发布落地页 URL                             | 无（内容侧自己链）                            | 未对接              |
| S   | 与客服 PRO 协同 | 把页上的人收成线索    | 页内客服位开关                                      | 无（客服侧按页接待）                           | 未对接              |

## 3. 能力 1：意图库存

没有意图对象，生成就是盲写。

**拉词自动，成意图要确认。** 新建/编辑/停用管的是已确认的意图对象，不是说词全靠手填。拉完词不会自动出页。


| 所需项      | 类型        | 做什么 | 关键对象 |
| -------- | --------- | --- | --- |
| 拉词进候选    | 产品功能      | 有授权则自动拉：Search Console 查询词、广告投放词、内容主题。进候选池，不是 Intent | 候选 |
| 确认为意图    | 产品功能      | 人从候选确认，或手建。确认后才有 Intent | `Intent` |
| 意图对象     | 产品功能      | 编辑/停用。字段：query（词或主题，可多个）、source（seo/sem/social/manual）、关联产品、stage、status | 同上 |
| 阶段判定     | **Agent** | 确认时把 query 判为了解/对比/决策；吃不准标待确认，人改 | `stage` |
| 人工指定一页   | 产品功能      | 展会、促销、老板点名：可不绑 Intent，直接选页面类型创建 | `source=manual` |


词和 `source` 是 **「这一页为谁而做」**，不是 **「已经被谁链过来」**。后者见能力 4。

不做：无授权硬接账户；拉词后自动出页；近义合并 Agent。无授权时允许只手建，闭环仍能转。

---

## 4. 能力 2：按主题出页

骨架由页面类型决定；阶段只作为生成约束。人工对话路径保持现状。页面类型可增，不限定个数。


| 所需项     | 类型               | 做什么                                                                 | 关键对象或出参                 |
| ------- | ---------------- | ------------------------------------------------------------------- | ----------------------- |
| 页面类型    | 产品功能             | 每种类型规定模块骨架、必问、默认 CTA。类型可扩展。生成时按该类型组装，一个类型可由多项生成能力组合，不在产品层绑定实现方式 | `page_type`             |
| 阶段约束    | 产品功能             | 了解：短表单、轻 CTA；决策：必须有转化口；无认证数据则隐藏认证模块                               | 规则，无配置后台                |
| 对话式人工创建 | 产品功能 + **Agent** | 现有：选页面类型 → 追问 → 调研 → 出稿确认 → 出页                                      | 草稿 HTML + 文字稿           |
| 由意图出页   | **Agent**        | 选词后一页预制方案（人可改）→ 开始生成 → 与本地相同：调研、确认区块文案、采纳后出页 | 页面草稿（未发布）               |
| 知识召回后写作 | **Agent**        | RAG 产品参数/案例/资质；无则隐藏，禁止虚构                                            | 带引用的文案块                 |
| 文字稿确认门  | **Agent**        | 与本地相同，采纳区块后才 render_page                                               | `requires_confirmation` |
| 页面质检    | **Agent**        | 有 H1、有与阶段匹配的 CTA/表单、无编造认证                                           | passed / hard_issues    |


对话创建和意图出页共用同一套页面类型，不拆两套出页逻辑。

## 5. 能力 3：发布成站内真页

没有 URL，内链和投放都落空。预览 HTML 只是草稿。发布能力走站点已有机制，落地页不自建 CMS。


| 所需项      | 类型        | 做什么                                        | 关键对象                      |
| -------- | --------- | ------------------------------------------ | ------------------------- |
| 发布到站点    | 产品功能      | 草稿 → 线上页；生成路径；记下 page_type、stage、intent_id | `LandingPage`（url、status） |
| SEO 基础字段 | 产品功能      | title、description、H1                       | Meta                      |
| SEO 字段生成 | **Agent** | 写 title/description，放进文字稿确认，不单独再开一轮        | Meta 草稿                   |
| 表单绑定     | 产品功能      | 绑定站点已有表单；没有则用页内默认表单                        | form_id（可选）               |


不做：自建版本回滚、301 规则、canonical 专项、发布前独立检查 Agent（质检已在能力 2）。

---

## 6. 能力 4：分发到达

人要到达的是 **匹配的意图页**，不是「任意打开了网站」。两条路都要有：外链直达；进了站但没落在匹配页上，再引导过去。

发链（文章里插 URL、广告填落地 URL）不在落地页里配置。横幅是站内引导，属于本功能。


| 层    | 是什么            | 在哪设置                            | 例子                     |
| ---- | -------------- | ------------------------------- | ---------------------- |
| 计划承接 | 这一页为哪些词、哪类渠道而做 | **本功能**：意图上的 `query` + `source` | 页承接「CNC OEM」；计划来源 seo  |
| 实际引用 | 谁真正把人带到这一页     | **不在本功能**：内容发文、广告落地 URL、社媒贴链    | 某篇博客插入该 URL；某广告组填该 URL |
| 实际来过 | 访客从哪来          | **不是设置**：访问/留资上的 UTM，能力 6 里看    | `utm_source=google`    |


| 所需项        | 类型   | 做什么 | 关键对象 |
| ---------- | ---- | --- | ---- |
| URL 目录     | 产品功能 | 已发布页列表：承接词、计划来源、阶段、页面类型、URL，供复制 | URL 列表 |
| 带参复制       | 产品功能 | 复制时可选填 UTM（投放的人填） | 一条带参 URL |
| 是否命中意图页    | 产品功能 | 这次访问打开的 URL，是不是该去的那张已发布意图页 | 命中 / 未命中 |
| 未命中则横幅引导   | 产品功能 | 能匹配到已发布意图页才出横幅，点进该 URL；匹配不上不出，避免乱导 | BannerRule |
| 服务端渲染约束    | 产品功能 | 爬虫拿原页 HTML，横幅不改写入收录的内容 | 对爬虫的原始 HTML |


命中判断和横幅先走规则（当前 URL、来源参数、内容页与意图词的对应），不上运行时 Agent。

不做：落地页上的「被哪些文章引用」配置清单、独立映射台、锚点 Agent、短链、分发状态机。

---

## 7. 能力 5：转化承接

转化口已经在各页面类型里。本能力只保证线索能记下来，并带上是哪一页、哪个意图、哪条渠道。


| 所需项  | 类型     | 做什么                                              | 关键对象 |
| ---- | ------ | ------------------------------------------------ | ---- |
| 页内表单 | 已在能力 2 | 各页面类型自带表单；阶段只约束字段多少（了解 3 个左右，决策不超过 6 个）          | 表单   |
| 线索写入 | 产品功能   | 提交写入询盘/CRM：page_id、intent_id、stage、page_type、UTM | Lead |
| 客服位  | 产品功能   | 页上开关，打开即嵌入客服 PRO                                 | 开关   |


不做：阶段表单模板库、离开挽留、选型器、落地页侧再做一个转化 Agent。按阶段选 CTA 已在出页时完成。

---

## 8. 能力 6：效果回流

成功标准是页有没有人、有没有留资。首期只出数，改页仍用现有对话，不上自动再生成。


| 所需项   | 类型           | 做什么                           | 关键对象 |
| ----- | ------------ | ----------------------------- | ---- |
| 按页统计  | 产品功能         | PV、表单提交；能按 UTM 来源筛            | 一页一行 |
| 不达标则改 | 人 + 现有 Agent | 运营看数，回到对话改页，或改意图上的词、或让内容/广告换链 | 新草稿  |


不做：覆盖率看板、达标线引擎、归因模型、诊断 Agent、自动再生成、行为分析。这些等有稳定流量再加。

行业库、引用可视化：有则用，没有不阻塞出页。

| 所需项   | 类型   | 说明                         |
| ----- | ---- | -------------------------- |

## 10. 业务链条

### 10.1 运营链：准备接流量


| 步骤  | 用到的能力           | 谁做                  | 产出        |
| --- | --------------- | ------------------- | --------- |
| 1   | 词进候选 / 确认为意图   | 自动拉候选，人确认或手建     | Intent    |
| 2   | 判定阶段            | **Agent**（人可改）      | stage     |
| 3   | 选定页面类型          | 默认映射，人可改            | page_type |
| 4   | 知识召回 + 按页面类型出稿 | **Agent**           | 文字稿       |
| 5   | 确认              | 人                   | 确认态       |
| 6   | 出页并发布           | **Agent** + 站点发布    | URL       |
| 7   | 把 URL 交出去       | 人从目录复制；内容发文按意图上的词插入 | 到达路径      |
| 8   | 看 PV / 提交       | 产品功能                | 报表        |
| 9   | 不好则改            | 人用对话改页              | 新版本       |


### 10.2 访客链：一股流量被接住


| 步骤 | 谁做 | 产出 |
| --- | --- | --- |
| 1 | 从搜索引擎 / 广告 / 社媒进入站点某一页 | 一次访问。可能直接是意图页，也可能是内容页/产品页。广告/社媒可带 UTM；Google 自然搜索当场通常不带查询词 |
| 2 | 判断是否命中意图页 | 命中：当前 URL 就是该去的已发布意图页。未命中：打开的是别的页 |
| 3 | 未命中则横幅（能匹配才出） | 点进匹配落地页，或匹配不上则不出横幅。爬虫走 SSR 原页 |
| 4 | 看匹配页内容，点 CTA、填表或开客服 | 停留 / 提交 |
| 5 | 线索带上页、意图、来源 | Lead → 回流运营链第 8 步 |

Search Console 的「查询词 × 页」事后回填意图候选（能力 1），不在这次点击上做判断。

### 10.3 使用链路（运营出页）

选候选词 = 选定意图。后面的确认项**合在一页、全部预制**，不要再拆「接什么 / 做成什么样」。点「开始生成」之后，**接回本地项目现有前端**：先确认页面区块和文案，采纳后再出页。

线框：AI智能落地页-出页向导线框.html（历史引用未随项目保存）

对人只有三步：


| 步 | 人做什么 | 系统做什么 |
| --- | --- | --- |
| 1 选意图 | 点一条候选词（或入口 B 一句话/选类型） | 词 + 来源进 Intent |
| 2 看预制方案 | 不对就改芯片；对就「开始生成」 | 结合关键词、来源、网站档案、知识库，一次填好阶段、页面类型、CTA、关联产品 |
| 3 确认文案再出页 | 和本地 demo 一样：确认各区块文案，采纳后出页 | 现有 `generate_copy_draft` 确认门 → `render_page`。出页后可发布拿 URL |


预制规则（写死，无配置后台）：


| 项 | 从哪来 |
| --- | --- |
| 承接词、计划渠道 | 候选词本身 |
| 阶段 | Agent 按词判了解/对比/决策 |
| 页面类型 | 了解→品牌实力；对比→产品营销；决策→留资获客（有活动才促销/展会） |
| 主 CTA | 随阶段：资料 / 看差异 / 获取报价 |
| 关联产品、公司、卖点、认证 | 网站档案 + 知识库；对不上词的产品不预勾 |
| 展会/促销缺事实 | 方案上标红，生成前补；补不上就停 |


不要点完词就自动生成。预制错了还能在第 2 步改；生成后再改成本高。  
不要再发明一套「预览页里改一句」替换文字稿确认——本地已经有区块确认，向导只负责把上下文喂进去，并跳过 `ask_user` 连环问。

**不塞进这三步的：** 带 UTM 复制、横幅/SSR、客服、效果报表。出页并发布之后再用。

硬闸：方案上没产品且知识库也补不上 → 不能开始生成；无事实不编造，区块标「缺××」或隐藏。

## 11. 9 月落地切分

原则：投入即产出；不新建模板体系。横幅/SSR、行为分析、A/B 不进首期实现，但能力表里保留。


| 批次    | 纳入 | 明确不做 |
| ----- | --- | --- |
| 已有    | 现有页面类型的对话出页、确认门、质检 | — |
| 首期 P0 | 意图可手建；阶段字段 + 约束写进生成；发布 URL + 基础 Meta；表单回写 page/意图/UTM；知识库 RAG | 拉词后自动出页、三套阶段模板 |
| 首期 P1 | 授权后拉词进候选（先 GSC）；URL 目录与带参复制；按页 PV/提交 | 落地页内「被引用清单」、锚点 Agent |
| 首期 P2 | 客服位开关；页上带 page 上下文给客服 | 诊断 Agent、自动再生成 |
| 后续    | 广告词同步；是否命中意图页 + 未命中横幅 + SSR；按效果自动改页 | A/B（需高流量） |

## 12. 一句话对照


| 现在                  | 闭环要变成                                                       |
| ------------------- | ----------------------------------------------------------- |
| 选一个玩法 → 说话 → 生成一页预览 | 意图带阶段 → 用现有玩法出页（阶段只改 CTA/表单）→ 发布成 URL → 人能点到 → 留下资 → 按页看数再改 |


产品功能负责：拉词候选与意图对象、页面类型、发布、URL 目录、命中判断与横幅（SSR）、线索回写、按页统计。  
Agent 负责判阶段、按页面类型写页、阶段约束、知识召回、确认门、质检。  
拉词自动，成意图和出页都要人确认。发链不在落地页里配；站内未命中用横幅接，不靠再配一张引用表。

## 13. 与本地营销页 Agent 怎么接

本地 `marketing-agent-app` **就是能力 2 的出页引擎**。新壳只做两件事：选意图、把预制方案喂进现有 session。点「开始生成」之后，**前端逻辑与本地项目相同**（调研 → 区块文案确认 → 采纳后 `render_page`）。不要另做预览改稿流程。

**接法：** 预制方案点「开始生成」→ `POST /marketing/setup` + `POST /chat/`，第一条消息带齐 query / source / stage / page_type / CTA / 产品。Agent **跳过 ask_user**，直接并发调研 → `generate_copy_draft`，停在现有文字稿确认门。用户采纳区块后 `render_page`。发布拿 URL 是本地没有的，出页后再加。

| --- | --- | --- | --- |

### 13.1 本地入参怎么喂

本地真正的业务入参**不是** `/marketing/setup` 里那三个字段。setup 只收 `page_type`（另加模型 Key）。业务全在第一条 `POST /chat/` 消息里，由 `buildContextMessage` 拼成 `[配置信息]` + `[需求]`。点「开始生成」仍走这一条，把预制方案写进这段文本，并注明「已齐，勿再 ask_user」。

**setup（会话壳）**


| 字段 | 现在 | 新链路 |
| --- | --- | --- |
| `page_type` | 左侧必选才能开聊 | 预制芯片，setup 照传 |
| `credential_id` / `model_name` | 配置模型 | 不动，不进方案 |


**第一条消息里现有入参 → 谁来预填**


| 本地字段 | 现在谁填 | 新链路 |
| --- | --- | --- |
| `[需求]` 用户原话 | 中间输入框 | 候选词本身（入口 B 才手打一句） |
| `pageType` | 左侧必选 | 阶段默认映射，方案上可改 |
| `CompanyInfo`（名/行业/产品/官网） | 登录后接口，现多 Mock | 网站档案预填，方案上只读展示 |
| `selectedProducts` | 侧栏点选 | 档案产品按词匹配预勾，方案上可改勾 |
| `sellingPoints` | 侧栏可选；空则对话里补 | 知识库/档案预填 |
| `targetAudience` | **prompts 规定必问** | 由词+阶段推断一句，写进配置；有则禁止再 ask_user |
| `contactInfo` | 侧栏 | 档案 |
| `selectedForms` | 侧栏 | 按阶段默认 inquiry/lead，人一般不用碰 |

| 留资：钩子内容 | **ask_user 必问** | 能从词推断则预填（如选型资料），可改 |


**开始生成之后工具自己拉（不要再做成方案表单）：**  
`fetch_company_info` · `fetch_product_list` · `fetch_brand_assets` · `web_search_competitors` · `analyze_industry`。预制用档案/知识库给出**展示用默认**；工具结果与预填冲突时，以工具+确认后的文字稿为准。

**`render_page` / `generate_copy_draft` 的参数**（headline、selling_points、products_json…）不是用户入参，是 Agent 在确认文案之后从文字稿和工具结果填进去的，链路不变。

新增、只写进 `[配置信息]`、本地今天没有的：`承接词`、`来源 source`、`阶段 stage`、`主 CTA`、`intent_id`。
