# 营销意图任务交接

先读取 [接口说明](references/protocol.md)，按 [JSON Schema](references/intent.schema.json) 组织任务；使用 [完整示例](references/intent.example.json) 作为结构参考，不直接复用其中业务标识或发布授权。

## 执行要点

1. 从当前业务任务取得来源 Agent、目标站点和意图。意图包含稳定 ID、指纹、主题、阶段、人群及具体需求。不要把原始访客聊天、个人联系方式作为默认参数。
2. 从平台可用配置选取页面类型、模板、转化动作、市场、语言、颜色、字体。模板必须属于所选页面类型。不要猜测不存在的模板、产品或素材 ID。
3. 填写知识目录与产品、素材引用。空知识目录表示检索全部授权目录。缺少资料允许生成占位草稿，但应进入 needs-input，不能用捏造的规格、认证或案例满足发布要求。
4. 只有当前任务已具有平台授予的站点发布权限，才设置 automatic 并填写真实 authorizationRef；否则使用 draft。JSON 中写入引用不会创建权限，也不能代替平台验证。
5. 同一次任务的重试保留 requestId 与参数。参数变化需要新 requestId。意图 ID/指纹用于内容关联，requestId 用于幂等，不要混用。
6. 验证 JSON Schema 及平台资源归属后，交给现有营销任务工具或服务。没有可用服务时输出 JSON 文件，不声称已发布。本项目可用原型的“导入意图”入口演示流程。
7. 接收状态：needs-input 时补充指定资料；completed 时记录 pageId、意图关联、链接与发布状态；failed 时按错误修正，不无上限重试。自动修正最多两轮，仍不达标转为待处理。

## 自动运行范围

生成助手制作内容，检测助手协调知识缺口与独立网站检测助手的报告。生成助手按报告执行允许的修改并复检。自动发布要求资源满足、AI 友好度至少 80、授权有效、推广配置有效，且没有未完成的检测或阻断项。只发布到指定站点和指定位置，不扩展为全站改动。

## 当前可用能力

这里是可复制分发的 Skill 包，尚未安装到任何 Agent 运行环境。当前项目只有前端导入与本地发布状态演示，无真实接口、鉴权、Agent 执行或网站发布。不要调用示例中的 demo 标识执行真实业务。
