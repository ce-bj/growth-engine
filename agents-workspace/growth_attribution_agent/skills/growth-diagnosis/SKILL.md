# 增长诊断

默认站点 `site_demo_b2b`。看回复的是老板和运营。快照已经算完三态、落点、假设和工单；本 Skill 只规定怎么读、怎么说、怎么交出去。

改措辞去改指标的 `plain` 字段，不用改本 Skill。对用户说话时不要出现内部字段名、编号代号；完整禁令见系统提示。

## 工具顺序

```text
get_snapshot(site_id)
→ 仅当 headline.问题页.路径 非空时，对该路径 get_page_content
→ 先读 headline，再按下面「怎么读快照」取字段
→ 默认摘要版；用户要细节才展开完整版
```

不要重算、不要改阈值、不要连打十余次取数。没有问题页就不要调 `get_page_content`。贴工单前用页正文核对首屏原文和参数，页面上没有的项不要写进提示词。缺产品 URL 就停下来问。

用户确认执行后，对内容类任务调用 `record_handoff_mock`。

## 怎么读快照

快照大约一千行。`headline` 已经把关键事实挑到最前，摘要只许用下面这些；把 `scan` 整表念出去，会把「少了 11 条询盘」说成内部口径的「持平」。

**摘要只用：**

| 说什么 | 取哪里 |
|---|---|
| 少了几条询盘、来了多少人 | `headline.询盘条数`、`headline.访客人数` |
| 卡在哪一步、哪一页 | `headline.卡在哪一步`、`headline.问题页` |
| 为什么 | `headline.根因`；有并列时再读 `headline.并列因素` |
| 现在能做什么 | `tasks[]` |
| 上月已改、还在等 | `headline.观察中一句话`；不要展开 `observing[]` |
| 数看不到 | `headline.数据缺口一句话` |

询盘条数照 `headline.询盘条数.少了几条` 说。它在 `scan` 里可能标「持平」，那是死档口径，对外说出来会像系统坏了。

**完整版再读：** `locate.excluded`（排除了什么）、`drill.anomaly_points` 与 `cross_check`（落到哪一页/哪条渠）、`hypotheses` 里 `result=pass` 且 `in_scope` 的 `name` 与 `evidence[].plain`（根因）、未命中的用 `failed_on.reason` 的人话。指标说法一律用切片上的 `plain`。

**完整版也不要念给用户：** `failed_on.clause`、`drill.scopes`、`scan` 里留资数的「持平」、假设 `id`、措施 `measure_id`。

根因只采用 `hypotheses` 中 `result=pass` 且 `in_scope` 的 `name`，按 `headline.根因` 的顺序并列，不要合成一条。`headline.并列因素` 是本层以外也成立的，放后面补一句即可。

百分比必须配绝对数或「每 100 个访客里有几个」。滚动深度这类写成「大部分人只翻到页面上面三分之一就走了」。

## 两档输出

| 档位 | 什么时候出 | 用哪些字段 |
|---|---|---|
| 摘要版 | 默认 | 见上一节「摘要只用」 |
| 完整版 | 用户说「详细依据 / 完整报告 / 排除了哪些 / 怎么算的 / 数据明细 / 展开」 | 六节，见下 |

摘要版不要编号小节。结构：

1. **开头一句**能独立看懂：询盘少了几条 → 因为什么 → 出在哪一页。
2. **发生了什么**：3 到 5 行。来的人多少、卡在哪一步、哪一页、什么时候开始的。
3. **现在能做什么**：按下一节写工单。
4. **观察中 / 缺口**：各最多一行；不影响结论的缺口不写。
5. **结尾**：可以追问「看详细依据」「排除了哪些可能」或某条来路的表现。

不含已贴交接提示词时，正文控制在 400 字以内。提示词必须整段贴出，不要为了字数缩成「请改首屏」。

完整版六节（术语第一次出现跟一句白话）：

1. **变化清单** ← `scan`（指标用 `plain` / 本期 / 基线 / 变化 / 三态）
2. **漏斗段定位** ← `locate.reason` + `locate.excluded`
3. **异常点** ← `drill.anomaly_points`；交叉看 `cross_check`（单渠还是同步变差）
4. **根因** ← 命中的假设 + `evidence`；未命中的用 `failed_on.reason` 写为什么排除
5. **任务说明** ← `tasks[]`，写法与摘要相同
6. **数据缺口** ← 照抄 `headline.数据缺口一句话` 或 `data_gaps`。看不到就说看不到，不要推断成「无缺口」

**示例（摘要开头，贯穿案例）：**

> 这个月询盘少了 11 条。人没少，是主力铝支架详情页第一屏没接住客户，看了上半屏就走了。

不要写成「留资率跌了 25.8%」或「留资数持平」。

## 工单与复盘

一期只能交接运营助手现网 Skill。`tasks[].handoff_prompt` 已经按欢迎语写好，优先原样贴出。不要发明做不到的动作（投放/SEO/外链、设计回滚、导航筛选、客服话术、系统挂表单、站内搜索同义词）。

| `execution.kind` | 怎么说 |
|---|---|
| `skill` | 一句这条要解决什么，然后原样贴 `handoff_prompt`（仍以欢迎语开头、带完整 URL），说明复制给运营助手。再补一句 `execution.cannot` |
| `display_only` | 写成「这条运营助手做不了，要人来处理」，给建议和原因。不要贴提示词，不要写成可点击执行 |
| `system` | 只说本期分析口径已标记 |

欢迎语只能是：帮我修改产品 / 帮我发布产品 / 帮我修改内容 / 帮我发布内容 / 帮我创建发布内容计划 / 帮我生成智能营销页 / 帮我查找并替换内容。改已有产品必须走「帮我修改产品」+ 产品 URL，不要用「帮我修改内容」改产品。

`observing[]` 是已改、还在等下一个完整自然月的工单。摘要用 `headline.观察中一句话` 提一句，不要再对同一页、同一改法出执行。`skipped_repeats` 同理，不要重开。

`review_due[]` 才到对照月。对照 `trial.snapshot_before` 说效果：绝对数按日均，并减掉全站同期变化。基数不够或全站也涨了同样多，结论写成「看不出」，不要说措施无效。观察月未结束不要提前下结论。

快照若标明某页在提升或保护位，不要对这页出改写工单；亮点只展示。

## 例外

- **北极星没破线**（`triggered.triggered` 为 false，且 `headline.根因` 为空）：说清楚询盘/留资没有跌到要开工会诊的程度。用户点了别的指标，用 `get_metric_detail` 回答那一条，不要把失败假设编成工单。
- **没有问题页**（`headline.问题页` 为空）：跳过读页。若卡在来人这一步，任务多半是仅展示的站外建议，按 `display_only` 写。
- **库里全不命中**（`headline.根因` 为空，且本层假设都未 pass）：`propose_hypothesis(name, layer, when_text, how_to_verify, metrics_needed)`。只有提议权，告诉用户待运营确认。根因非空就不要提候选。
- **路径 UV**：用户说「帮我查路径UV」时，把原话或「路径UV」原样传入 `get_metric_detail`。不要改写成 `UV@路径` / `UV@页面`。返回 `ok: false` 时用 `candidates` 里的 `ref` 再查，不要自己拼名字。
