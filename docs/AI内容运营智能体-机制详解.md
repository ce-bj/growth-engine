# AI 内容运营智能体 · 机制详解（逻辑、标准与原理）

> 这份文档不堆术语，专讲"为什么"和"怎么判"。
> 配套：总览见《汇报材料》；模块清单见《产品逻辑 v1》。本文是它们的"白话版 + 标准细则"。

## 开篇：这套系统为什么长这样

先抛开 M1–M7 这些编号。整套系统其实只为回答 **4 个根本问题**，每个模块都是为回答其中一个而存在：

| 根本问题 | 对应能力 | 大白话 |
|---|---|---|
| **写什么？** | 数据监控 + 环境感知 | 从站内数据和站外信号里，找出"该写 / 该改"的内容 |
| **怎么写？** | 内容策略 + 生成 | 定选题、调资料、起草，按一套写法规矩产出 |
| **写得好不好？** | 质量管控 | 用一套可量化的标准打分、卡红线，不过就打回 |
| **怎么越写越准？** | 自动复盘 + 工作记忆 | 看发布后的真实效果，把"管用的写法"记下来，下次自动用 |

这 4 步首尾相接，形成一个**闭环**：

```
写什么 → 怎么写 → 写得好不好 → 发布 → 看效果 → 记下来 →（下周）写什么
   ↑                                                      │
   └──────────────── 经验回流，下一轮更准 ────────────────┘
```

**为什么必须是闭环，而不是"写完就完"？**
因为内容效果好不好，只有发布后才知道。如果智能体不回头看自己写的东西有没有人读、读得深不深，它就永远在"凭通用经验瞎写"，不会进步。闭环 + 记忆，才是"智能体"和"群发工具"的本质区别。

## 一、模块背后的逻辑：每个模块在解决什么"为什么"

下面用大白话讲清每个模块的存在理由，以及它们之间的**因果链**。

**M1 数据监控 —— 解决"我知道该写什么吗？"**
不监控，策略就是拍脑袋。监控给的是"哪篇表现差、哪篇过时了"的事实依据。
关键认知：**监控数据只用于决定"接下来写什么/改什么"，不是对外的效果承诺**。收录、排名由搜索引擎决定，本产品不打包票（见下文"增信"一节）。

**M2 环境感知 —— 解决"外面发生什么影响我该写什么？"**
搜索引擎算法变了、AI 搜索会不会引用我、竞品在写什么热点、行业出了什么新政——这些站外信号会直接改变选题口径。不感知，就等于闭门造车。
边界：竞品可以"看"，但**采集的竞品信息隔离存储，正文绝不出竞品名、绝不做对比**——保留选题价值，杜绝误入成稿。

**M4 内容策略 —— 解决"写什么、按什么比例、什么顺序？"**
把 M1/M2 的信号变成一张可执行周历：
- **4:3:3 配比**：引流内容 40%（拉新曝光）、品牌内容 30%（建立信任调性）、深度阅读内容 30%（推动读完）。比例不是随便定的，是"曝光/信任/消费"三种目标各占一块。
- **关键词排序**：不是谁热写谁，而是按"意图强度 × 竞争度"排（详见第二节）。
- **旧内容三触发**：排名下滑 / 效果低 / 数据过时，命中任一就进补强队列——**改旧的比写新的更划算**。
- **热点四关**：相关 → 合规 → 可信 → 可达，四关全过才追，防盲目蹭热点。

**M5 质量管控 —— 解决"写出来的东西合格吗？"**
这是"增信"的硬把关。不是二值"过/不过"，而是**0–100 评分 + 分级门禁 + 红线**（详见第二节）。

**M6 A/B 实验 —— 解决"哪种写法读者更买账？"**
对高流量页，系统只**出方案和建议**，分流执行交给 CMS（不越界）。比的是标题、封面、引导位置、结构顺序这些"影响阅读深度且可逆"的呈现层，不碰正文事实。

**M7 自动复盘 —— 解决"我上周期干得怎样、下次怎么改？"**
周维度对比"高深度阅读 vs 低深度阅读"内容的差异，把规律写进工作记忆，回流到 M4/M5/M1（详见第五节）。

> **关于 M3 知识库**：它不是本产品的模块，是**外部独立产品**。本产品只做"只读调用"——写之前调它的资料组装上下文，质检时对照它检查。它建不建、怎么建是另一个产品的事。本产品自己的"经验"存在 M7 的轻量工作记忆里（见第五节）。

## 二、标准究竟怎么判断（评分细则与判定公式）

这是用户最该看透的部分。下面把每一条标准拆成"高分长什么样 / 低分长什么样 / 怎么算通过"。

### 2.1 EEAT 评分（0–100，四维各 25 分）

EEAT 是 Google 评价内容可信度的框架（Experience 经验 / Expertise 专业 / Authoritativeness 权威 / Trustworthiness 可信）。我们把它变成可打分的尺子：

| 维度 | 25 分长什么样（拿满分） | 低分长什么样（扣到 0） | 判定要点 |
|---|---|---|---|
| **E 经验** | 有真实案例、实测数据、一线细节。如"我们实测 PT100 在 -50°C 偏差 0.3°C" | 全是"温度传感器很准""质量可靠"这类空话 | 有没有**具体场景 + 真实数字**，而非形容词堆砌 |
| **E 专业** | 术语准确、参数正确、引用行业认证。如型号、量程、精度等级写对，标注 IEC 60751 | 术语混用、参数写错、张冠李戴 | 外行看不出，但内行一眼能判"这人懂行吗" |
| **A 权威** | 作者/机构背书、引用来源。如引用行业白皮书、官方手册、署名工程师 | 匿名、无出处、"据说""一般人认为" | 内容**挂在谁的名下、能不能被溯源** |
| **T 可信** | 结构化标记、信源可点击、有更新日期。如"最后更新 2026-09"、链接可点 | 无日期、链接死链、通篇无出处 | 读者**自己能不能验证** |

**分档门禁（写完后立刻判）**：
- **≥80 分**：自动放行（人不用管）
- **60–79 分**：警告级，交人确认（人点一下）
- **<60 分**：风险级，自动退回重写

> 为什么升"评分"而不是"过/不过"？因为分数能驱动复盘和策略调整——"这篇 72 分主要卡在权威维度"比"不通过"有用得多。

### 2.2 GEO 适配检查（5 项，每项过/不过）

GEO（生成引擎优化）= 让内容更容易被 AI 搜索（豆包、DeepSeek、ChatGPT 等）摘引和推荐。5 项：

| # | 检查项 | 怎么算通过 | 为什么 |
|---|---|---|---|
| 1 | 结构清晰 | H2/H3 层级规范，不跳级 | AI 靠结构理解内容 |
| 2 | 结论明确 | 首段直接给核心结论，不是"本文将介绍…" | AI 摘引要的是结论句 |
| 3 | 有信源 | ≥1 个可点击的**高权威**源（按 M2 权威度库判定） | 没出处 AI 不敢引 |
| 4 | 含 FAQ | ≥3 组问答，覆盖读者核心疑问 | FAQ 是 AI 最喜欢摘的块 |
| 5 | 可引用短句 | 存在适合被 AI 直接摘的结论句 | 如"PT100 在 -200~850°C 线性度优于热电偶" |

输出：GEO 分 + 缺项清单 → 自动补 FAQ / 信源，或提示人补。

### 2.3 风险级硬底线（任何策略下都拦截，不破例）

这条没有商量余地，命中即**自动退回**：
- **事实错误**：参数写错（如把量程写错一个数量级）
- **虚构案例**：编了一个不存在的客户故事 / 使用场景
- **虚构资质**：声称有实际上没有的认证 / 奖项 / 合作

为什么是"硬"的？因为一旦内容造假，信任归零，且可能违法。策略再急、人再想要，这条都不让过。

### 2.4 深度阅读率与基线判定

- **深度阅读率** = 停留时长 / 内容篇幅比（读完没读完，而不是划走）
- **基线按站点配，不跨站共用**：中文站和日文站流量体量可能差 10 倍，共用阈值必然误报。基线来自该站过去 90 天数据的中位数。
- **判定规则**：单篇 PV 达站点基线 **且** 深度阅读率 ≥ 阈值 **且** 跳出率 ≤ 阈值 → 良好；任一项不满足 → 待优化。

### 2.5 关键词排序公式

```
排序分 = 搜索意图强度 × 竞争度倒数
```
- **意图强度**：购买/咨询意图 > 信息意图。从历史点击、询盘推断（想买的人搜的词，比随便看看的人搜的词，价值更高）。
- **竞争度倒数**：头部内容越强、排名越难，竞争度越高，倒数越小，排序越靠后——**专挑"值得写又写得动"的词**。
- v14 老版只算了意图、没算竞争度，所以会去抢根本写不上的热词，这版补上。

## 三、为什么就能增信（信任到底从哪来）

"增信"不是一句口号，它对应读者信任的 **5 个具体来源**，每个来源都有机制兜底：

| 读者信任来源 | 我们的机制 | 为什么管用 |
|---|---|---|
| **像内行** | EEAT 的"经验 + 专业"维度：真实案例、实测数据、准确术语 | 浏览者分不清真假，但能识别"这人懂行"。具体参数、一线细节是强信号——写"偏差 0.3°C"比写"很准"可信 10 倍 |
| **有出处** | GEO 的"有信源"+ EEAT 的"权威/可信"：可点击权威源、更新日期、署名 | 读者自己能点过去验证，怀疑就降下去了。"他说有依据"不如"他自己把依据摆出来" |
| **不过时** | 旧内容三触发（含时间戳 >180 天自动进补强）+ T 维度的"更新日期" | 客户看到 2023 年的参数会犯嘀咕；标"最后更新 2026-09"等于告诉他们"这是当下的" |
| **能快速找到答案** | GEO 的"结构清晰 + FAQ≥3" | 读者有具体疑问，FAQ 直接给答案，信任来自"你懂我的顾虑" |
| **被第三方背书** | GEO 适配 → 被 AI 搜索摘引推荐 | 新维度：AI 把你的内容当答案推给别人，等于搜索引擎替你背书 |

**一个关键认知**：我们**不承诺**"收录、排名、曝光、询盘"——这些是搜索引擎和投放决定的外部变量。我们说"增信"，是说**内容本身做到专业、有据、可信**。这恰恰是浏览者"信不信"的决定因素，也是我们交付得稳的部分。

**为什么"像内行"比"喊口号"更能增信？**
信任来自"可验证的信号"而非"自我宣称"。一个声称"行业领先"的网站，和一个写出"PT100 在 -200~850°C 线性度优于热电偶、附 IEC 60751 标准链接"的网站，后者让工程师一眼信。我们的整套质检，本质就是把"可验证信号"变成写作的硬要求。

## 四、生产的内容怎么贴合当前网站（不跑题的机制）

智能体不是凭空编内容，它"认识"你的网站，靠四层 grounding（落地锚定）：

**① 只读调用知识库产品（资料的源头）**
写之前，调知识库拿：品牌词库、产品参数、行业知识、既有内容资产。并且**记录"本次引用了哪些条目"**，用于溯源。
- 例：写《PT100 选型指南补强版》时，调出 PT100 参数 48 条、引用其中 12 条，复用站内《故障排查手册》1 篇。

**② 品牌一致性多语言扫描**
全文扫描对照品牌词库，确保各语种写法一致。
- 例：中文"铂电阻"、英文"PT100"、日文"白金測温抵抗体"在公司品牌库里是同一概念的三种写法，智能体会照此统一，不会乱翻译。

**③ 站点基线独立配置**
每个站独立配置：阈值、语种、目标市场。智能体按"这个站"的标准判断好坏，不会拿英文站的标准套日文站。

**④ 旧内容补强，而非另起炉灶**
识别站内**已有**内容的陈旧 / 低效，优先补强——既贴合网站既有结构，又比从零写更省、更连贯。
- 例：发现英文站《PT100 选型指南》402 天未更新、参数停留在 2023 版 → 触发"数据过时"，生成补强版而非新写一篇。

**⑤ 选题贴合站点历史表现**
关键词排序、4:3:3 配比都参考该站过去的数据，而不是套用通用模板。

**一个完整例子（termoline.com · 中/英/日 3 站 · 工业温度传感器）**：
> 智能体发现英文站《PT100 选型指南》402 天未更新（M1 触发"数据过时"）→ 调知识库拿最新参数（48 条引 12 条）、复用站内《故障排查手册》（M4 组装上下文）→ 按"产品类·英文站"写法起草，对照品牌词库确保术语一致（M5 品牌一致性）→ EEAT 自检 82 分（经验维因含实测数据满分）、GEO 5 项全过 → 自动放行 → 发布后进入监控。全程内容都锚定在"这个站、这类产品、这套参数"上，不会跑题。

## 五、自进化逻辑究竟是什么（从"随机写"到"越写越准"）

这是用户点名没说清的部分。下面用**机制 + 时间线**彻底讲透。

### 5.1 起点：智能体一开始也只是"按规矩写"

上线第一周，智能体只有**通用规则**（EEAT/GEO 标准、4:3:3 配比、关键词公式），它**不知道"这个站、这类内容"什么写法最有效**。它写出来的东西合格，但未必"最对胃口"。

### 5.2 每周复盘：从真实效果里提取规律

周维度对比"高深度阅读率"和"低深度阅读率"的内容，提取**差异特征**：

| 观察到的现象 | 提取出的规律 | 动作 |
|---|---|---|
| 带实测数据的选型指南，深度阅读率比泛泛科普高 2.3 倍 | "产品类内容含实测数据 → 更被读完" | 记入工作记忆 |
| 周五上午发布的 CTR 比平均高 18% | "周五上午发布对工业类目更优" | 记入工作记忆 |
| 标题带具体参数的，跳出率低 12% | "标题含具体参数 → 留住人" | 记入工作记忆 |

### 5.3 工作记忆结构（只存自己的经验）

写入格式：
```
{ 规律描述, 适用语种/类目, 效果证据, 来源任务, 置信度, 有效期 }
```
例：
```
{
  规律: "工业传感器类目带实测数据可提升深度阅读",
  适用: 英/日站 · 产品类,
  证据: 近4周3篇对比, 深度阅读率 +2.3x,
  置信度: 0.7,
  有效期: 90天
}
```

**关键约束（为什么不会"学歪"）**：
- **只存经验，不存事实**：品牌信息、行业知识、内容资产一律从知识库读，不复制到记忆里——避免和独立知识库产品重叠、污染。
- **置信度随验证次数更新**：同规律被验证越多，置信度越高。
- **证伪即降权/移除**：某次写了实测数据但深度阅读仍低 → 置信度下调，低于阈值就剔除。这保证旧经验不会用一辈子。
- **有效期**：过期自动失效，逼系统用近期数据。

### 5.4 三个自动应用触发点（被调用才算"进化"）

记下来的规律**不是睡在库里**，而是自动回流到生产：

| 触发点 | 怎么用 | 效果 |
|---|---|---|
| **M4 日历** | 下周同类目选题，优先排"带实测数据"的写法 | 好写法被更多采用 |
| **M5 质检** | 自动追加检查项"是否含实测数据" | 好写法被强制固化 |
| **M1 基线** | 按表现调站点基准线（如深度阅读率阈值 40%→45%） | 标准随能力提升而提高 |

### 5.5 提交知识库产品的边界

高置信规律（如置信度 >0.9 且跨多站验证）作为**候选**提交给知识库产品，由那侧判定是否成为"公司级事实知识"。本产品**不自行写库**——经验归经验，事实归事实。

### 5.6 一个 8 周演化时间线（直观看"越用越好"）

| 周次 | 状态 | 深度阅读率（产品类平均） | 变化 |
|---|---|---|---|
| 第 1 周 | 只按通用规则写，4:3:3 随机排 | 38% | 基线 |
| 第 4 周 | 发现"实测数据"规律（置信度 0.7），M4 已开始优先排、M5 已加检查项 | 47% | +9pt |
| 第 8 周 | 规律置信度 0.9，跨英/日站验证，提交知识库产品候选；基线阈值已调至 45% | 52% | +14pt vs 第1周 |

**这就是"智能体"和"群发工具"的分界**：工具永远重复同一套动作；智能体因为"看效果 → 记规律 → 自动改自己"，第 8 周比第 1 周明显更懂这个站。

## 六、一句话串起来（给汇报用）

我们做一个**替你把多语言站点内容写出来、并做到专业可信的 AI 智能体**：它靠监控和感知决定写什么（M1/M2），按一套可量化标准产出并卡红线（M4/M5），发布后看真实阅读效果、把管用的写法记进自己的经验库并自动改下一周的策略（M6/M7）——**闭环 + 记忆**让它越用越贴合你的网站、越写越准，而每一篇都锚定在你的品牌资料和站点基线之上，所以内容不跑题、有据可查、让人信得过。我们不承诺收录和排名（那是外部变量），只把"内容本身"做到位。
