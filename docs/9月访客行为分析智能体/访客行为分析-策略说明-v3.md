## 一、机制总览

### 1.1 一句话

扫描站点 28 天行为数据，给每个访客打参与深度标签（窗口内跨访问取最深一级），按"页面 × 人群"看数据表现；每种表现直接映射一个内容行动。一张映射表讲完全部产品逻辑。

### 1.2 输入 → 规则 → 输出

| 环节  | 内容                                                                |
| --- | ----------------------------------------------------------------- |
| 输入  | 站点 × 28天窗口的行为数据包（页面访问序列、停留、滚动、转化交互事件【表单开始编辑 / 智能客服开聊】、站内搜索）       |
| 规则  | 每条规则 = 数据表现（触发条件）+ 诊断结论 + 内容行动。规则并行、互不依赖                          |
| 输出  | 两类：**任务说明**（写到子智能体入参级，展示给客户、确认后调用子智能体执行）/ **仅展示建议**（站外或技术事项，人来处理） |

### 1.3 四类内容行动（封闭清单，不允许发明第 5 种）

本智能体是**诊断方**：只出数据表现、诊断结论、内容行动建议，不直接改页、不直接发布。执行由对应子智能体完成，本智能体交出去的是**任务说明**——既是子智能体的入参，也同时展示给客户看（规范见 1.5）。

| #   | 行动             | 执行方式            | 什么时候用                                             |
| --- | -------------- | --------------- | ------------------------------------------------- |
| 1   | **生成/重做营销页**   | 任务说明 → 营销页子智能体  | 某类来意没有专属承接页；已有营销页接不住。任务说明必须附带横幅弹出时机配置（见附录 B）      |
| 2   | **修改/生成产品详情页** | 任务说明 → 产品详情子智能体 | 详情页首屏没接住、缺信任要素、缺参数前置；或型号有需求无详情页                   |
| 3   | **内容发布计划**     | 任务说明 → 内容计划子智能体 | 要靠持续内容承接一批需求（搜索词、对比主题、行业资讯），而不是改一页                |
| 4   | **站外建议**       | 仅展示，不出任务说明      | 投放、SEO、外链、表单字段结构、技术故障、导航调整——内容动作解决不了的，给建议和原因，人来处理 |

### 1.4 三个诊断轴

| 轴         | 看什么                | 回答什么              |
| --------- | ------------------ | ----------------- |
| 轴一：访客意图驱动 | 各深度等级人群的规模、卡点、集中页面 | 哪个阶段的人没被接住、该给什么内容 |
| 轴二：页面表现驱动 | 页面自身指标破线           | 这个页面哪里坏了          |
| 轴三：内容供给驱动 | 访客行为暗示的缺失          | 站内缺什么页面、缺什么内容     |

三轴并行扫描，同页多命中按第五章优先级处理。

### 1.5 漏斗流失点分布总览

| 流失点   | 含义      | 命中规则                                            | 条数  |
| ----- | ------- | ----------------------------------------------- | --- |
| 流失点 1 | 进来了没看进去 | A-01、A-02、B-01、B-03、B-04、C-01、C-02、C-03（主）、C-04 | 9   |
| 流失点 2 | 看进去了没动手 | A-03、A-04、A-05、A-06、B-02、C-03（兼）                | 6   |
| 流失点 3 | 动手了没留下  | A-07、A-08                                       | 2   |

分布本身就是一个诊断信号：一期规则重在前两层（内容能不能接住人），流失点 3 只有 2 条且都偏站外建议——因为留资环节的表单结构不是内容智能体能改的。如果客户站的流失主要卡在流失点 3，本产品的可执行空间有限，要如实说明。

## 二、意图体系（5 级参与深度）

### 2.1 分群定义与两层口径

意图回答"这个访客走到哪一步了"。按参与深度分 5 级。定义按 B2B 工厂站实况适配（比较不依赖价格页、决策不依赖 FAQ/合同页，规则可按站点页面结构配置）。

**B2B 采购决策周期长，一个买家一个月来 3-5 次是常态**：第一次探索、第三次比较、第五次询价。深度必须在访客维度跨访问累加，不能按天切断。因此打标分两层：

| 层 | 单位 | 怎么算 | 用在哪 |
|----|------|--------|--------|
| **访问级深度** | 访客 × 单次访问（会话） | 按 2.2 规则判这一次访问走到哪级 | 流失型判定（摩擦发生在具体某次访问）；横幅触发条件；路径明细展示 |
| **窗口访客深度（主口径）** | 访客 × 28天窗口 | 取窗口内所有访问的**最深一级**（流失型除外，见下） | 人群规则的分布与计数；一人多次访问只算一个人，不重复计 |

窗口层的两个伴随字段：

| 字段 | 含义 | 用途 |
|------|------|------|
| 访问次数 | 窗口内来了几次 | ≥ 2 次为回访访客，高价值人群，工作台单独可筛 |
| 深度轨迹 | 窗口后半段（近 14 天）最深 vs 前半段最深 | **推进**（后半段更深）/ **停滞**（多次访问深度不变，卡住了）/ **回退**。停滞本身就是诊断信号 |

5 级定义（访问级判定条件，每级按枚举条件判；窗口深度 = 各次访问取最深）：

| 等级      | 数据表现（单次访问打标条件）                                                                                                           | 业务含义                    | 该给什么内容                      |
| ------- | ------------------------------------------------------------------------------------------------------------------------ | ----------------------- | --------------------------- |
| **浏览型** | 以下四条**同时满足**：① 浏览页数 1-2 页；② 总停留 < 15s；③ 滚动深度 < 25%；④ 无转化交互动作（无表单开始编辑、无智能客服开聊）                                            | 扫一眼就走：误入、来意没被接住、或第一屏没抓住 | 首屏 3 秒内说清"你是谁、有什么、跟他什么关系"   |
| **探索型** | 满足其一：① 浏览页数 ≥ 3 页；② 存在合格浏览页（单页停留 ≥ 15s）；③ 滚动深度 ≥ 25% 的页面 ≥ 2 个。且未命中流失型/决策型/比较型任一条件                                       | 有需求在了解，但没到选型和询价         | 深度内容：案例、应用效果、参数详情、引导下一步     |
| **比较型** | 满足其一：① 同类页面组内来回切换 ≥ 2 次（A→B→A 记 1 次）；② 合格浏览的产品详情页 ≥ 3 个且跨品类/型号；且未命中流失型/决策型                                               | 在选型、在纠结"哪个适合我"          | 对比内容：型号横向对比、选型指南、适用场景标注     |
| **决策型** | 满足其一：① 表单开始编辑（表单字段获得焦点且有输入行为）；② 智能客服开聊；③ 访问联系/询价类页面且停留 ≥ 15s；④ 访问信任保障类页面（FAQ/资质/售后/合同条款）且停留 ≥ 15s。且未命中流失型                | 快动手了，在做最后确认             | 信任要素：认证、保障承诺、响应时效 + 低摩擦留资路径 |
| **流失型** | 满足其一：① 表单放弃（表单开始编辑后失焦无值且未提交，也无智能客服开聊兜底）；② 页面停留 > 60s 且无任何交互事件（需排除标签页切走，document.hidden 不计）。**一期不含"点击无响应"**（需全站点击埋点，二期补齐） | 卡在具体摩擦点上                | 修复摩擦点；内容动作救不了的走站外建议         |

**互斥与兜底**：判定按 流失型 → 决策型 → 比较型 → 探索型 顺序检查，命中即停；四级全不命中即为浏览型（兜底，此时浏览型四条枚举天然满足）。分类互斥且穷尽。

### 2.2 打标规则

**第一步：访问级判定**（每次访问按优先级扫，命中即停；条件与 2.1 枚举一致）

| 优先级 | 等级 | 打标条件（单次访问内，满足其一即命中） | 数据来源 |
|--------|------|---------|---------|
| 1 | 流失型 | ① 表单放弃（表单开始编辑后失焦无值且未提交，也无智能客服开聊兜底）② 停留 > 60s 且无任何交互（排除标签页切走）。一期不含"点击无响应" | 表单事件、事件流 |
| 2 | 决策型 | ① 表单开始编辑 ② 智能客服开聊 ③ contact 类页面停留 ≥ 15s ④ 信任保障类页面停留 ≥ 15s | 表单事件、客服事件、页面访问+停留 |
| 3 | 比较型 | ① 同类页面组来回切换 ≥ 2 次（A→B→A 记 1 次）② 合格浏览产品详情页 ≥ 3 个且跨品类/型号 ③ 同类页面组内浏览器后退 ≥ 2 次 | 页面访问序列 |
| 4 | 探索型 | ① 浏览页数 ≥ 3 ② 任一页停留 ≥ 15s ③ 滚动 ≥ 25% 的页面 ≥ 2 个 | 页面数、停留时长、滚动深度 |
| 5 | 浏览型 | 兜底：以上全未命中（此时"1-2 页 + 总停留 < 15s + 滚动 < 25% + 无转化交互"天然成立） | — |

**第二步：窗口级聚合**（28天窗口，按访客聚合）

| 字段 | 算法 |
|------|------|
| 窗口深度（主口径） | 窗口内所有访问的深度取**最深一级**（浏览 < 探索 < 比较 < 决策） |
| 流失标记 | 窗口内**任一次访问**出现流失型 → 该访客带流失标记，与其窗口深度**并存**（如"决策型 · 有流失信号"）。流失不覆盖深度——上周到过决策型、这次表单放弃的人，是"最该救的人"，不是"流失型的人" |
| 访问次数 | 窗口内访问次数（会话切分：无操作 30 分钟或过 0 点新开） |
| 深度轨迹 | 后半段（近 14 天）最深 vs 前半段最深：更深 = 推进；相同且访问 ≥ 2 次 = 停滞；更浅 = 回退 |

**同类页面组定义（配置项）**：同品类的产品详情页之间、案例页之间、营销页之间、同主题资讯页之间。分组依赖 2.3 的页面类型归类结果（pagetype + 页面名称 + URL 三重启发式），归类不准的页面不进组、不参与切换检测，避免误判比较型。运营可配置。

**跨设备说明**：窗口访客以 cookie 为身份，同一人换设备/清 cookie 会被算成两个访客，深度无法跨设备累加。一期接受此局限，不引入登录态识别；留资后的线索归人另走 CRM，不在本产品范围。

### 2.3 页面类型（决定行动落到哪个载体）

深度等级说"人走到哪了"，页面类型说"行动改到哪"。两维交叉出具体动作。

**现网实况（必须先说清）**：设计器后台的页面类型字段只有 **3 类：列表 / 综合 / 详情**。此外可用的只有两个自定义字段——**页面名称**（设计师建页时自己起的名字）和 **URL**（也可自定义）。所以细粒度页面类型**没有权威字段可取，只能尽可能枚举**：用 pagetype + 页面名称关键词 + URL 模式三重启发式归类，归不准的进"待人工校正"，不硬猜。

| 归类目标        | 现网 pagetype | 页面名称/URL 启发式（尽力枚举，可配置）                          | 主要动作方向               |
| ----------- | ----------- | ----------------------------------------------- | -------------------- |
| 产品详情页       | 详情          | 名称含"产品/型号/规格"，或 URL 含 /product_detail/          | 修改/生成产品详情页           |
| 产品列表页       | 列表          | URL 含 /products/，或名称含"产品中心/全部产品"                | 引导结构（站外建议）           |
| 营销页（落地页）    | 综合          | 由智能营销页能力生成的页面（**建议建页时打来源标记**，否则只能靠名称/URL 猜）     | 生成/重做营销页             |
| 联系/询价页      | 综合          | 名称含"联系/询价/留言"，或 URL 含 /contact/ /inquiry/       | 表单问题走站外建议            |
| 资讯/文章页      | 综合          | 名称含"新闻/资讯/动态/知识"，或 URL 含 /news/ /blog/          | 内容发布计划               |
| 案例页         | 综合          | 名称含"案例/客户/应用"，或 URL 含 /case/                    | 内容发布计划（补案例）          |
| 公司信息/资质/工厂页 | 综合          | 名称含"关于我们/公司/资质/荣誉/工厂"，或 URL 含 /about/ /factory/ | 信任素材前置到详情页/营销页       |

| 待人工校正       | 任意          | 三重启发式都不命中或互相矛盾                                  | 不产生页面级动作，进校正队列       |

**这条的产品要求（要提给设计器/建站侧）**：

1. **营销页要有来源标记**——由智能营销页能力生成的页面，建页时写入一个可识别标记（模板ID或来源字段）。否则"营销页 vs 普通综合页"只能靠名称猜，C-02/A-02 的准确率没保障。
2. **页面类型枚举建议扩展**——事件表备注已写"页面类型待产品枚举：产品详情/首页/列表/落地页/文章/关于等"。一期若后台不改，就走上面的启发式；若能把 pagetype 扩到 8-9 类，轴一轴三的规则准确率会有质的提升。**这是投入产出比最高的一项改造。**
3. **启发式规则是配置项**，运营可按客户站的实际命名习惯调整，不写死在代码里。

## 三、三轴映射规则表

每条规则三段式：**数据表现 → 诊断结论 → 内容行动**。行动只从 4 类里选，写到执行方不需要再猜的粒度。

**数据表现只回答一个问题**：什么对象、什么指标到什么数值 = 命中这条。不写分支、不写加重信号、不写旁证。

**双轨判定（通用，不逐条重复）**：下文所有绝对线阈值同时适用环比线（定义见附录 C.1）。绝对线命中 或 环比线命中，任一成立即算该条件满足。冷启动期（上线不满 4 周）只有绝对线可命中。规则正文只写绝对线数值，不再逐条标"或 ↓环比"。

**人群计数约定**：下文"探索型访客""比较型访客""决策型访客"均指窗口访客深度（28 天取最深，见 2.1），一人只算一个，不再逐条标"窗口"。

**其他约定**：

| 写法 | 含义 |
|------|------|
| `指标 < X`（严重 < Y） | 绝对线。X = 警戒线，Y = 严重线（严重线命中时额外在页头结论点名） |
| `｜` | 同一条件内的多个信号，任一成立即算该条件满足 |
| `基数：N` | 最低样本量，不足则不判定、进数据缺口 |
| 指标名(编号) | 编号 = 《111 指标字典》序号，便于研发对口径 |

## 四、优先级、查重、复盘与升级

### 4.1 优先级与去重

| 情况 | 处理 |
|------|------|
| 同页命中多轴 | 轴二（页面自身坏了）优先出任务说明；轴一其次；轴三是新建载体，与前两者不冲突可并行 |
| 同轴多条命中同页 | 按偏离程度（指标变化绝对值最大）或影响人数排，取第一条出任务说明，其余作佐证附在任务说明里 |
| A-02 与 C-02 同时命中 | 同一事实，合并为一份生成营销页任务说明 |
| 全站 ≥ 5 页命中同一规则 | 不逐页出任务说明，升级为站点级建议："全站首屏可能存在共性问题"，客户确认范围后再拆页出任务说明 |
| 同页同改法在观察中 | 上期已出任务说明且客户已确认执行、对照窗口未到 → 本期不重复出，标注"上期措施观察中" |
| 同页 28 天内已出过同类任务说明 | 不重复出 |

### 4.2 内容查重（新建类行动的前置闸门）

轴三和 A-02/A-03/A-05 的行动是**新建载体**（生成营销页、发布产品详情页、建内容发布计划）。子智能体真会建页——不查重就会同一个来意建三个营销页、同一个型号建两个详情页，站内越改越乱。

**规则**：任何"新建"类任务说明在交给子智能体之前，必须先过查重闸门。

| 步骤 | 做什么 |
|------|--------|
| 1 检索 | 按任务说明的目标（来意描述/关键词/型号/主题）检索站内已有页面：页面名称、URL、正文主题、已有营销页的来意标记 |
| 2 判相似 | 主题相似度 > 70% 视为已有承接页（相似度按标题+首屏+主题词计算，具体算法与研发定） |
| 3 改行动 | 命中已有页 → **任务说明从"新建"改写为"修改已有页"**，写清已有页 URL 和改哪几段；未命中 → 才走新建 |
| 4 例外 | 已有页虽主题相同但**页面类型不对**（如来意该落营销页，现有的只是资讯文章），仍允许新建，但任务说明里必须写清"已有 XX 页是文章体，不承接询价来意，故新建" |

**查重结果要写进任务说明的"确认点"**，让客户看见："站内已有 2 个页面主题相近（列 URL），建议改这两页而不是新建；如确认新建请说明理由。"

> 这一条对内容发布计划尤其重要：计划的关键词清单要先和站内已有文章比对，已覆盖的词从清单里剔除，只发真正缺的。

### 4.3 复盘与效果评估基准

**复盘判定原则**（沿用原 PRD）：执行月的下一个完整自然月做对照，绝对数按日均并减掉全站同期变化；基数够且全站没同步涨才说效果，否则说"看不出"，不写措施无效。

**每条规则自己的达标线**——光有"基数够不够"不足以判断措施有没有用，还要有"用到什么程度算成功"。评估指标按规则命中时的破线指标反向定：

| 规则 | 评估指标 | 达标基准（对照月 vs 冻结月） |
|------|---------|---------------------------|
| A-01 浏览型占比高 | 该页浏览型占比 | 下降 ≥ 10pp |
| A-02 / C-02 无专属营销页 | 新营销页的落地接住率；该渠道秒退率 | 新页接住率 ≥ 全站均值；渠道秒退率下降 ≥ 10pp |
| A-03 探索型到不了询价 | 探索型→决策型的升级比例；详情页到达率 | 升级比例提升 ≥ 5pp |
| A-04 深读不动手 | 该页转化交互率 | 提升 ≥ 2pp（相对提升 ≥ 20%） |
| A-05 比较型卡住 | 比较型→决策型升级比例；对比页/横幅到达率 | 升级比例提升 ≥ 5pp |
| A-06 缺选型内容 | 该品类资讯/选型内容的合格浏览访客；搜索0结果率 | 内容有读者（日均合格浏览 ≥ 5 人）；0结果率下降 |
| A-07 决策型没留资 | 留资完成率；开聊留资率 | 完成率提升 ≥ 3pp |
| A-08 表单放弃 | 表单完成率 | 提升 ≥ 5pp |
| B-01 首屏没接住 | 该页落地接住率、落地停留均值、滚动P75 | 接住率提升 ≥ 10pp，且停留均值回升 |
| B-02 高看低转 | 该页转化交互率 | 提升 ≥ 2pp |
| B-03 秒退飙升 | 该页落地接住率（秒退的反面） | 提升 ≥ 10pp |
| B-04 内容老化 | 该页停留均值、滚动P75 | 停留均值止跌回升 ≥ 15% |
| C-01 搜索无承接 | 该词搜索0结果率、搜后离站率 | 0结果率归零；搜后离站率下降 ≥ 20pp |
| C-03 无详情页 | 新详情页的合格浏览访客、转化交互率 | 日均合格浏览 ≥ 5 人；有转化交互发生 |
| C-04 资讯供给不足 | 资讯类页面访客数、合格浏览率 | 访客数提升 ≥ 20%，合格浏览率不低于全站均值 |
| 横幅弹出（附录 B） | 横幅曝光→点击率、点击→转化交互率 | 点击率 ≥ 5%；点击后有转化交互发生 |

**达标也要双轨判**（对应附录 C.1）：环比改善不等于修好了。

| 环比 | 绝对线 | 结论 |
|------|--------|------|
| 改善 | 已达标（回到警戒线内） | **真见效**，沉淀经验 |
| 改善 | 仍不达标 | **"好转但没修好"**：如落地停留均值从 8s 涨到 14s，环比 +75% 但仍低于 15s 门槛 → 不算见效，进 4.4 升级换改法 |
| 无变化 | 仍不达标 | 措施无效，进 4.4 升级 |
| 看不出（基数不够/全站同步变化） | — | 不判失败，继续观察一个窗口 |

**判定三态**：达标 = 见效；未达标但基数够且全站没同步涨 = 措施可能不对，进 4.4 升级；基数不够或全站同步变化 = "看不出"，不判措施无效，继续观察一个窗口。

**最终对外仍要落到北极星**：以上都是过程指标，复盘结论对外一句话要说清"询盘（留资数）拿回来几条"。过程指标达标但留资没动，如实说"页面接住了，但询盘没起来，下一步看流失点 2/3"。

### 4.4 行动升级机制（闭环）

任务说明不是发出去就结束。形成"出任务说明 → 客户确认执行 → 观察 → 评估 → 升级或沉淀"的闭环：

```
出任务说明
   ↓ 客户确认
子智能体执行
   ↓ 进入观察中（同页同改法不再重复出）
对照窗口到（执行月下一完整自然月）
   ↓ 按 4.3 达标线评估
   ├─ 达标 → 见效，沉淀为经验（哪类数据表现 + 哪类改法有效）
   ├─ 看不出（基数不够/全站同步变化）→ 继续观察一个窗口，不判失败
   └─ 未达标（基数够且全站没同步涨）→ 升级
                    ↓
        升级第 1 次：换改法重出任务说明
          （如首屏改法无效 → 从"改文案"升级为"改结构/参数前置"，或改走生成营销页分流）
                    ↓
        升级第 2 次仍未达标：转人工
          出「仅展示建议」：说明两轮改了什么、数据怎么变的、为什么内容动作可能不够，
          建议人工排查（版式回滚、导航结构、投放来意、产品本身竞争力）
                    ↓
        同一页同一问题不再自动出第 3 轮任务说明
```

**升级规则要点**：

| 规则 | 说明 |
|------|------|
| 不无限重试 | 同一页同一问题最多 2 轮任务说明，第 3 轮强制转人工建议 |
| 换改法不换问题 | 升级时必须换一种改法（改文案→改结构→换载体），不允许把同一套改法再发一遍 |
| 升级要带证据 | 转人工的建议里必须写清两轮各改了什么、指标怎么变的，让人接手时不用重新查 |
| 客户可否决 | 客户认为诊断不对时可否决，否决理由沉淀下来（是数据问题还是判断问题），作为口径校准输入 |
| 误报台账 | 每季度拉一次：误报多则收紧阈值，漏报多则放宽。数据来自复盘和客户否决记录，不另采 |

## 五、贯穿案例

某铝制品工厂站，28 天窗口扫描完成，主力型号详情页 `/products/aluminum-bracket`：

| 命中规则 | 数据表现 |
|---------|---------|
| A-01 | 浏览型占比 40% → 78%（+38pp），UV 156 |
| B-01 | 落地停留 84s → 26s（−69%），滚动 P75 72% → 33% |
| B-03 | 秒退率 22% → 47%（+25pp） |

**冲突处理**：三条命中同一页，轴二 B-01 为主任务说明，A-01/B-03 作佐证合并。三条同指 **流失点 1**（访问入口→有效浏览）——人进来了没看进去。

**输出任务说明 1（修改产品详情页 → 产品详情子智能体，客户可见）**：

> **任务目标**：主力铝支架详情页首屏没接住访客，卡在流失点 1（进来了没看进去）——落地停留 84s→26s，滚动 P75 72%→33%，秒退率 22%→47%。把首屏从公司介绍改为产品直答。
> **任务对象**：https://www.example.com/products/aluminum-bracket
> **内容要求**：第一屏改成"铝支架 6063-T5 + 给谁用 + 核心参数（抗压强度、壁厚、表面处理）前置"；当前首屏原文是"XX铝业有限公司成立于2005年，位于佛山市南海区……"；参数现在在第三屏，挪到首屏可见区；没有确切数字的项写"待填写"。
> **约束**：局部修改，不整页重写，不改标题，保留正文原有配图；覆盖上线前先出方案预览。
> **确认点**：待填写的抗压强度/壁厚数值请客户补充；首屏方案确认后执行。

**输出任务说明 2（配套·生成营销页 → 营销页子智能体，客户确认后执行）**：

> **任务目标**：为铝支架品类采购来意生成询价型营销页，承接详情页改好后引入的流量。
> **任务对象**：目标网站 = 当前站点；新建页面。
> **内容要求**：页面类型 = 询价型；来意描述 = 铝支架品类采购；关联产品 = 6063-T5 系列；卖点从详情页提取；买家 = 待填写。**横幅弹出时机** = 附录 B 时机 1（探索型达成时，第 2 个合格浏览的产品详情页页底横幅）。
> **确认点**：买家画像与联系方式请客户补充。

**对外一句话**：询盘少了 11 条，人没少，是主力铝支架详情页第一屏没接住——看了上半屏就走了。

## 六、一期范围

### 6.1 筛选标准

数据可得（现有埋点能算）+ 执行可达（任务说明有对应子智能体承接，或明确为仅展示建议）+ 结论可讲（一句话能说清）。

### 6.2 一期规则清单

| 规则 | 数据可得 | 执行可达 | 结论 |
|------|---------|---------|------|
| A-01 浏览型占比高 | ✓ 页面数+停留 | ✓ 详情页/营销页子智能体 | 进一期 |
| A-02 浏览型集中通用页 | ✓ 渠道UV+落地页+秒退 | ✓ 营销页子智能体 | 进一期 |
| A-03 探索型到不了询价 | ✓ 页面访问序列 | ✓ 营销页子智能体 | 进一期 |
| A-04 探索型深读不动手 | ✓ 停留+转化交互事件 | ✓ 详情页子智能体 | 进一期 |
| A-05 比较型卡住 | ⚠️ 依赖页面序列的切换检测 | ✓ 营销页子智能体 | 进一期（切换检测需联调验证） |
| A-06 比较型缺选型内容 | ⚠️ 依赖站内搜索 | ✓ 内容计划子智能体 | 有条件进（搜索可用时） |
| A-07 决策型没留资 | ✓ contact页访问+表单/客服事件 | ✓ 详情页子智能体 + 仅展示 | 进一期 |

### 6.4 横幅弹出时机

- 二期：实时 SDK 上线后按已落库配置激活

实时弹窗/挽回干预执行、A/B 测试、CTA 点击采集与点击类摩擦信号（rage click / dead click，现网无此埋点）、按来源关键词打标（数据不可得）、跨站行业基准、ML 意图模型（先规则打标）。

## 七、对外怎么讲

**给老板（30秒）**：给每个访客打深度标签——浏览、探索、比较、决策、流失。哪个阶段的人卡住了、卡在哪个页面，直接映射成内容动作：生成营销页、改详情页、发内容计划、站外建议。营销页生成时连"什么时候弹横幅"一起配好。

**给客户（1分钟）**：你的网站每天有人来，有人扫一眼就走，有人看了半天不询价，有人填了一半表单跑了。访客行为分析告诉你每个阶段卡了多少人、卡在哪个页面、为什么，然后直接给出任务说明——该生成的营销页、该改的详情页、该发的内容，写清楚改哪里、改成什么样。你确认后，对应的智能体去执行。

**给研发（3分钟）**：一个规则引擎。前置模块两步打标：先给每次访问判 5 级深度（规则打标，命中即停），再按访客聚合 28 天窗口——窗口深度取最深一级，流失标记并存，带访问次数和深度轨迹。然后 16 条规则并行扫描，每条就是 if 数据表现 then 诊断结论 + 内容行动。行动只有 4 类，前 3 类输出任务说明（写到子智能体入参级，客户可见，确认后调用营销页/产品详情/内容计划子智能体执行），第 4 类仅展示建议。本智能体自己不执行。同页多命中按轴二 > 轴一 > 轴三取主任务。所有阈值、页面类型归类、同类页面组定义都是配置项。

## 附录 C · 阈值配置表（全部为配置项）

### C.1 三态判定：绝对线 + 环比线双轨

**为什么必须双轨**：一期刚上线没有上期数据，环比线跑不起来；而"页面有流量但绝对值就是差"本身已经是确定的问题，不需要对比期才能下结论。字典里已有这个写法的先例——**全站留资率**（指标2）是"环比跌 >20% **或绝对值 <0.5%**"，**滚动深度P75**（指标54）在假设方案库第 6 条是"异常 **或低于 40%**"。本文档把这个模式扩到全部指标。

**判定规则**：

| 轨 | 何时生效 | 怎么判 |
|----|---------|--------|
| **绝对线**（常驻） | 上线第一天起，永久有效 | 指标绝对值越过警戒线 → 异常；越过严重线 → 异常且在页头结论点名 |
| **环比线**（字典口径） | 采满 4 周基线后叠加 | 见 C.1.2 |
| 合成 | 两轨都可用时 | **任一命中即异常**。绝对线不因有了基线而废弃 |

**绝对线必须叠加最低基数**，否则小流量页天然误报：落地页访客 / 页面UV ≥ 30、全站有效浏览访客 ≥ 10、全站转化交互访客 ≥ 10、周期 ≥ 14 天（环比线才需要）。基数不够时不出结论，进数据缺口。

#### C.1.1 环比线（直接沿用《111 指标字典》，不另定）

| 项 | 字典口径 |

| 率类指标 | 异常 = **环比跌 > 10% 且绝对跌 > 2pp（须同时满足）**；提升 = 环比涨 > 10% 且绝对涨 > 2pp；其余持平 |

#### C.1.3 冷启动与校准

| 阶段 | 判定方式 | 对外怎么说 |
|------|---------|-----------|
| 上线第 1-4 周（基线采集中） | **只跑绝对线**。环比线不出结论 | 不报"持平"，报"基线采集中，本期按绝对标准体检"。绝对线命中的照常出任务说明 |
| 第 5 周起 | 绝对线 + 环比线双轨，任一命中即异常 | 正常口径："环比变差"或"绝对值不达标"，两者都写清是哪一轨命中的 |
| 连采 4 周后回调 | 取同类页面（同页面类型分组）各指标的实际分布：**P25 → 警戒线，P10 → 严重线**，替换上表"待校准"项 | 回调只改配置表，不改代码 |
| 每季度 | 拉误报/漏报台账：误报多则收紧绝对线，漏报多则放宽 | 数据来自复盘结果与客户否决记录，不另采 |

**冷启动期的额外保护**：

1. 绝对线命中但**基数不足**（落地页访客 < 30 等）→ 不出任务说明，进数据缺口，标"流量不足，暂不判定"
2. 绝对线命中但**该页刚发布不足 14 天** → 降级为提示，不出任务说明（新页数据不稳）
3. 冷启动期**不判"提升"**（没有基线就没有提升），只判异常与达标
4. 首次体检报告须写明："本期为冷启动体检，依据绝对标准线；环比结论自 XX 日起可用"

> 规则正文的"数据表现"已把绝对线数值**内联写出**（如 B-01 的"落地停留均值 < 20s（严重 < 15s）"），不再写"判为异常"让读者翻表。**本表是阈值的唯一权威来源**：规则里出现的数值与此表一致，调阈值时只改本表配置，规则正文引用配置项，不硬编码。逆向指标（秒退率、0结果率、搜后离站率、未转化页出口率、浏览型占比）用 `↑环比`，其余用 `↓环比`。
