# AI 内容运营智能体 · 标准细则（把"怎么判"落到可执行）

> 本文是《机制详解》的**标准补漏版**：把其中"没说清 / 对不上 / 含糊带过"的 6 点 + 自查发现的薄弱项，全部给到**具体指标、公式、阈值、接口现状**。
> 状态标签诚实区分能力成熟度：
> - ✅【有接口/可自动】现在就能跑
> - 🟡【需自建/估算】要补能力或靠近似
> - ⚪【待标定/待配置】参数需落地时定，本文给默认建议值
>
> 所有标准均可回溯源文档《产品逻辑 v1》；本文新增的具体数值为**可执行建议值**，上线前需回测标定。

## 一、数据监控到底监控了什么

监控分 **站点层**（配置与聚合）和 **内容层**（判定与执行单元）。全部数据**只用于决定"接下来写什么/改什么"**，不是对外效果承诺。

### 1.1 监控维度总表

| 维度 | 指标 | 频率 | 数据来源 | 状态 |
|---|---|---|---|---|
| 站点·流量 | PV、UV、新访客占比 | 日 | 站点埋点 | ✅ |
| 站点·质量 | 跳出率、平均停留时长、停留达标率 | 日 | 站点埋点 | ✅（埋点需新接） |
| 站点·行为 | 点击热图 | 周 | 热力工具（自建/第三方） | 🟡 |
| 站点·流转 | 站内下一页跳转率、⌀会话深度 | 周 | 站点埋点 | ✅ |
| 内容·搜索 | 关键词排名、曝光量、点击量、CTR | 周 | 各站搜索引擎站长平台（GSC/Bing Webmaster 等） | ✅（官方 API） |
| 内容·消费 | 单篇 PV、深度阅读率 | 周 | 站点埋点 | ✅ |

### 1.2 触发动作（监控→执行）

| 判定条件 | 动作 | 流向 |
|---|---|---|
| 单篇 PV < 站点基线 | 自动发起「补强」任务 | → M4 排期 |
| 单篇深度阅读率 < 阈值 | 标「待优化」，进补强队列 | → M4 |
| 整站周环比下滑 ≥ **X%** | 触发 M7 整体下滑诊断 | → M7 |
| 关键词排名跌出前三页 / 降 ≥ **N** 位 | 进 M4 旧内容优化队列 | → M4 |
| 热图关键区块无点击 | 生成页面结构优化建议 | → 可进 M6 测试 |

> **前置依赖（不做则 M1 转不动）**：① 跳出率/停留/热图埋点 ② 各站站长平台接入（排名/曝光/CTR）。GSC 是唯一一手、免费、准确的自有数据，应作为 M1 第一数据源。

## 二、环境感知的逻辑

逻辑主线：**外部信号 → 采集 → 判定 → 只改"选题口径"和"GEO 策略"，绝不进成稿。**

### 2.1 六类信号的处理逻辑

| 信号 | 采集方式 | 判定逻辑 | 下游用途 | 状态 |
|---|---|---|---|---|
| 搜索引擎算法更新 | 三源交叉：①SEO 社区/官方博客 ②自有全站排名与收录突变 ③行业媒体聚合 | 交叉命中 → 标「疑似/确认」两级（不能归因到具体更新） | 调 M4 选题口径 | ✅（波动指数 Semrush Sensor 等免费） |
| AI 搜索引用 | **主动探针**：固定 prompt 向豆包/DeepSeek/文心一言等提问，抓是否引用、位置、锚文本 | 算引用率、Top1 首推率、被引 URL | 调 M5 GEO 策略 | ✅（第三方 GEO API） |
| 竞品内容 | 竞品 sitemap + RSS 增量抓取；排名用 rank tracker API | 提取高排名/高互动话题 | 仅驱动 M4 选题信号 | ✅ |
| 行业新闻/政策 | RSS + 官方站点订阅 + 关键词过滤 | 生成热点候选、政策变动标记 | M4 热点响应 | ✅（成本极低） |
| 上升趋势词 | GSC 查询增量（首选，自有数据）+ Google Trends/百度指数/5118 | 给趋势词 + 上升强度 | M4 选题 | ✅ |
| 媒体权威度 | 初始人工录入 + 探针持续验证（被引频次→更新评级） | 评高/中/低权威 | M4 信源 / M5 GEO 检查 | 🟡（无现成库，需自建+养） |

### 2.2 竞品隔离边界（硬规则）

采集竞品**允许**，但：隔离存储（打「选题参考」标签）→ 不进知识库正文区、不进生成上下文 → 仅驱动 M4 选题；**正文禁提竞品名、禁出现对比句式**。

### 2.3 媒体权威度库结构（🟡 需自建）

```
{ 媒体名, 类型(新闻/行业/论坛/社媒), AI引用倾向(高/中/低), 语种, 行业, 最近验证时间 }
```

**"养"的方法（一期→二期）**：
- 一期（静态分级）：行业垂直度（是否垂直工业/医疗等） + 域名权重（DR/DA/流量）人工评级。
- 二期（动态修正）：用 GEO 探针反查该域名在各 AI 回答中被引用的频次，频次高→上调权威度。

## 三、4:3:3 配比的依据，以及什么内容决定它

### 3.1 三类目标映射

| 类型 | 占比 | 目标 | 衡量指标 | 典型内容 |
|---|---|---|---|---|
| 引流内容 | 40% | 拉新曝光 | 曝光量、排名、新访客占比 | 行业趋势解读、热点科普、长尾词解答 |
| 品牌内容 | 30% | 建立调性与信任 | 停留时长、深度阅读率、品牌词搜索 | 公司理念、客户故事、价值观、品牌壁垒 |
| 深度阅读意图内容 | 30% | 推动深度消费 | 深度阅读率、下一页跳转率、CTA 点击 | 选型指南、故障排查、参数对比、白皮书 |

### 3.2 配比的"依据"是什么（诚实说明）

- **来源**：原规划为「引流/转化/品牌 = 4:3:3」的营销漏斗结构；本期转化不纳入，第三类替换为**深度阅读意图内容**，配比结构沿用。即 4:3:3 是**继承来的初始默认**，不是从本站数据推导出的铁律。
- **⚪ 可配置、可漂移**：M4 监控"三类配比偏差"作为指标；M7 复盘若发现某类持续低效，会经人工确认后调整配比（如品牌内容长期深度阅读率低 → 下调至 25%、引流升至 45%）。
- **所以"决定 4:3:3 的内容"是**：每周选题候选被打上「引流/品牌/深度阅读」类型标签后，按目标配比排进周历；配比本身由"站点目标 + M7 复盘"共同决定，不是固定写死。

## 四、质量管控的信源从哪来 + 有没有接口（关键诚实章）

这是你点名最尖锐的一问。分两层说清。

### 4.1 信源的两种身份

| 信源用途 | 来自哪 | 接口现状 |
|---|---|---|
| **① 内容引用源**（成稿里"可点击的来源"） | **知识库产品**（品牌资产/行业知识/官方手册/白皮书），本产品**只读调用** | ✅ 知识库产品提供只读接口；调用时记录"本次引用了哪些条目"溯源 |
| **② 权威度判定**（判断某个外部媒体算不算"高权威"） | **M2 媒体权威度库**（本产品自建） | 🟡 无现成数据源，需自建+养（见 2.3） |

### 4.2 各数据源接口现状一览

| 数据 | 有无直接接口 | 说明 |
|---|---|---|
| 知识库产品（只读） | ✅ 有 | 由知识库产品提供，本产品只调不写 |
| AI 搜索引用探针（GEO） | ✅ 有商业 API | 国内豆包/DeepSeek/文心一言等、国际 ChatGPT/Perplexity 等；约 $0.25/次 |
| 搜索引擎站长平台（排名/曝光/CTR） | ✅ 有官方 API | GSC、Bing Webmaster 等，一手免费 |
| 竞品 sitemap/RSS | ✅ 有 | 公开抓取 |
| 行业 RSS/政策源 | ✅ 有 | 公开订阅 |
| 媒体权威度库 | 🟡 无现成 | 需自建（行业垂直度+域权重 → 二期 GEO 反查） |
| 趋势词 | ✅ 有（GSC 查询增量最准） | GSC + Trends/指数/5118 补充 |

### 4.3 没有接口时，怎么知道信源（降级链）

1. **知识库接口不可用 / 条目缺失** → 内容标记「未引用知识库」，质检对应维度**降级提示，不阻断流程**（宁可少引用也不编造）。
2. **媒体权威度库无数据（一期）** → GEO「有信源」项按**静态分级**判定（行业垂直 + 域名权重）；二期接 GEO 反查后修正。
3. **信源有效性验证** → 用 GEO 探针反查该域名是否被各 AI 平台引用，频次高→权威度高（动态修正）。
4. **⚠️ 诚实难点**：AI **无法 100% 判定"信源真不真/内容有无虚构"**。兜底机制是：知识库参数对照（自动）+ 高风险项抽样人工复核 + 用户举报通道。这是"风险级硬底线"能拦住大部分、但需人兜底的现实。

## 五、深度阅读率与基线判定具体规则

### 5.1 定义

```
深度阅读率 = 停留时长 / 内容篇幅比
```
（读完没读完，而非划走；篇幅按字数/阅读所需时长归一）

### 5.2 基线算法（⚪ 本文建议，待实现确认）

- **按语种独立计算**，不跨站共用（中文站与日文站体量可能差 10 倍）。
- **算法**：取该站**过去 90 天同语种内容**的 PV、深度阅读率、跳出率的**滚动中位数**作为基线；M1 可随规律调整（见 M7）。
- **可配参数**：每站独立配置 PV 基准、UV 基准、深度阅读率阈值、跳出率上限。

### 5.3 判定规则（三条件 AND）

| 条件 | 关系 | 说明 |
|---|---|---|
| 单篇 PV ≥ 站点 PV 基线 | AND | 有足够样本量才评判 |
| 深度阅读率 ≥ 阈值 | AND | ⚪ 默认建议 ≥ 40%，按站调 |
| 跳出率 ≤ 上限 | AND | ⚪ 默认建议 ≤ 65%，按站调 |

三者全满足 → **良好**；任一项不满足 → **待优化**（进 M4 补强）。

### 5.4 具体阈值状态（⚪ 待配置）

源文档以 **X% / N 位** 作占位，落地时定。默认建议：

| 参数 | 默认建议值 | 说明 |
|---|---|---|
| 整站环比下滑触发诊断 | ≥ 15% | 周环比 |
| 排名跌出 | 前三页 / 降 ≥ 10 位 | 进旧内容队列 |
| 数据过时 | 含时间戳/价格/法规 > 180 天 | 或被子 M2 政策变动命中 |
| 深度阅读率阈值 | ≥ 40% | 按站调 |
| 跳出率上限 | ≤ 65% | 按站调 |

## 六、关键词排序公式的来源与标准

### 6.1 公式

```
排序分 = 搜索意图强度 × 竞争度倒数
排序分归一化到 [0,1] 后降序，取 Top N 进周历
```

### 6.2 意图强度（来源 + 分级标准 ⚪ 待标定）

- **来源**：关键词库分类（信息/导航/交易意图）+ 该站历史表现（GSC 查询类型、点击、询盘转化）。
- **分级标准（建议值）**：

| 意图 | 强度 | 依据 |
|---|---|---|
| 交易意图（买/询价） | 1.0 | "PT100 价格""厂家直销"类 |
| 咨询意图（怎么选/怎么用） | 0.8 | "怎么选型""哪个精度好"类 |
| 信息意图（了解概念） | 0.5 | "什么是 PT100"类 |

### 6.3 竞争度倒数（来源 + 计算）

- **来源**：站长平台排名数据 + 竞品排名追踪（rank tracker API）。
- **计算**：`竞争度 = 归一化(头部内容域权重均值 × 排名稳固度)` → 取倒数。

| 情形 | 竞争度 | 倒数 | 含义 |
|---|---|---|---|
| 头部全高权站、排名稳固 | 0.9 | 0.11 | 难写，靠后 |
| 长尾、低竞争 | 0.2 | 0.50 | 易写，靠前 |

- **⚪ 诚实**：意图/竞争的权重是**初始标定**，需经 M7 复盘 + 数据回测调参；v14 老版只算意图缺竞争度，会去抢写不上的热词，这版补上。

## 七、自查补漏：其他需要给具体标准的地方

下面是机制详解里我也没讲透、自查补上的项。

### 7.1 EEAT 打分卡（每维拆子项 + 权重）

| 维度(25) | 子项 | 分值 | 给分规则 |
|---|---|---|---|
| E 经验 | 真实案例 | 10 | 有具体客户/场景案例给满，泛泛给 0–5 |
| | 实测数据 | 10 | 有具体数字/测试结果给满 |
| | 一线细节 | 5 | 有操作细节/坑点给满 |
| E 专业 | 术语准确 | 10 | 术语无误给满，混用扣分 |
| | 参数正确 | 10 | 与知识库参数对照一致给满，错一处扣光 |
| | 行业认证引用 | 5 | 引用 IEC/ISO 等标准给满 |
| A 权威 | 作者/机构署名 | 10 | 署名工程师/机构给满 |
| | 引用来源 | 10 | ≥1 可点击源给满 |
| | 第三方背书 | 5 | 有外部推荐/认证给满 |
| T 可信 | 结构化标记 | 8 | 有 H2/H3/FAQ 结构给满 |
| | 信源可点击 | 9 | 链接有效可点给满 |
| | 更新日期 | 8 | 标"最后更新 YYYY-MM"给满 |

**门禁**：≥80 自动放行 / 60–79 交人 / <60 退回。

### 7.2 GEO 5 项量化阈值

| # | 项 | 量化判定 |
|---|---|---|
| 1 | 结构清晰 | 自动检测 H2/H3 无跳级（如 H1→H3 跳级即不通过） |
| 2 | 结论明确 | 首段 ≤120 字内含判断句（"是/指/即/核心"）半自动判，存疑交人 |
| 3 | 有信源 | ≥1 个媒体权威度库标记"高"的可点击源 |
| 4 | 含 FAQ | ≥3 组 Q&A（正则检测 Q:/A: 或结构化块）**硬阈值** |
| 5 | 可引用短句 | 存在 ≤40 字结论句（NLP 抽取，如"PT100 在 -200~850°C 线性度优于热电偶"） |

### 7.3 风险级硬底线的自动判定边界（⚠️ 诚实）

| 红线项 | 能否自动 | 方式 |
|---|---|---|
| 事实错误（参数错） | ✅ 能 | 成稿参数与知识库对照，不符即退回 |
| 禁用词命中 | ✅ 能 | 禁用词库匹配 |
| 抄袭 ≥15% | ✅ 能 | 相似度比对 |
| 品牌词不一致 | ✅ 能 | 多语言品牌词库扫描 |
| 虚构案例 | 🟡 部分 | 无知识库对应记录且无法验证→标记高风险，抽样人工 |
| 虚构资质 | 🟡 部分 | 需人工核对证书库 / 用户举报 |

> 结论：确定项全自动拦截；"虚构"类需人兜底 + 举报通道。任何策略下红线不破例。

### 7.4 工作记忆置信度更新公式

```
置信度_new = (n × 置信度_old + 本次结果×1) / (n + 1)    指数平滑
```
- n = 已验证次数；本次结果 = 成功(1)/失败(0)。
- 被证伪（连续失败）→ 置信度跌破阈值（如 <0.3）自动移除。
- 有效期到期自动失效，逼系统用近期数据。

### 7.5 效果归因的"差异特征"怎么提取

| 特征 | 提取方式 |
|---|---|
| 标题长度 / 是否含参数 / 是否含 FAQ / 发布时段 / 信源数 / 内容类型 | 结构化字段直接对比 |
| 主题分类、可读性分数、情感倾向 | NLP 抽取 |
| "为什么这篇好"的因果解释 | 人工抽样标注校准（每周抽 10%） |

### 7.6 A/B 显著性参数（确认，已有）

最小样本 = 每 variant ≥ 站点日均 UV × 最小周期；最小周期默认 14 天（最短 7 天）；置信度 95%（p<0.05）；双比例 z 检验（点击率/深度阅读率）。达显著→全量采用+写 M7 经验。

### 7.7 媒体权威度"养"的具体步骤

1. 建媒体清单（行业垂直媒体 + 综合媒体 + 论坛/社媒）。
2. 一期：人工按「行业垂直度 + 域名权重(DR/DA)」标高/中/低。
3. 二期：GEO 探针每周反查各域名被 AI 引用频次，频次高→上调。
4. 月更新，记录最近验证时间。
